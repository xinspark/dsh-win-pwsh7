# 05 · 装好了仍被拦：执行器缓存不会因安装而失效

- 类别: 运行时状态
- 日期: 2026-10-27
- 状态: 已修复（0.13.1）

## 症状

`pwsh7_install` 的作业报告 PowerShell 7.6.9 已安装，但同一个 DSH 进程里的 `pwsh` 工具
仍然被 gate 拒绝，`pwsh7_status` 甚至可能说 “Nothing to configure”。重启 DSH 或手动 pin
`pwsh-sandbox.pwshPath` 后才恢复。

## 根因

`PwshLocalExecutor.pwshPath` 是一个带缓存的 getter：只有当**声明的配置值**（`config.pwshPath`）
变化时才重新 `resolvePwshPath()`。Store 安装在插件外部完成，没有改声明值，所以 getter
一直返回启动时缓存的 5.1 路径；而插件的独立 resolver 已经能找到新装的 Store 别名，两者
不一致，报告就会把“resolver 找到了”误当成“执行器会运行它”。

## 证据

- `CHANGELOG.md` 0.13.1 节：安装后向 `declaredPwshPath` 写 sentinel 并重读 getter，强制
  同一 getter 重新解析；`resolvedPwshPath` 一起重置；
- `tools/check-native-contracts.mjs` 断言 `PwshLocalExecutor` 仍保留
  `declaredPwshPath` / `resolvedPwshPath` 缓存字段，并在 getter 变化时重解析；
- `tools/check-host.mjs` 的 `a cache nudge refreshes the live executor after an install` 用
  可变的桩 executor 复现“缓存 5.1 → 安装后 7.6.6”；`a live 5.1 executor is never reported as
  natively picked up` 断言状态不会再误报 “Nothing to configure”；
- 没有缓存字段的组合会退回“pin + reload”指引，而不是假装已就绪。

## 结论

1. 判断“会运行什么”必须读执行器 getter，不能读独立 resolver；
2. 安装后要主动打破执行器的缓存，但这是实现细节：必须 feature-detect，字段缺失时如实退回
   手动 pin；
3. 缓存刷新失败时，报告要说清“仍在 5.1”，不要输出自相矛盾的成功文案。
