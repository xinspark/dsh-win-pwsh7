# 08 · 同一个版本号，两个渠道，不是同一份文件

- 类别: 诊断 / 升级对账
- 日期: 2026-11-19
- 状态: 已固化（0.2.12；`tools/reconcile-build.mjs`）

## 症状

实例从 `0.2.2-rc.3` 升到 `0.2.2-rc.5`，五套门全绿、实机全绿，但做包级对账时工具报出
**"1 个文件变了"**：`dsh-pwsh-local/lib/index.js`。

如果就此收工，结论会是"上游改了执行器"——于是去读 diff：asar 里那份比 tarball 多三行

```js
// Desktop: piped Python stdio follows the ANSI code page (GBK on zh-CN Windows), but
// ENCODING_PREAMBLE makes PowerShell decode native output as UTF-8.
PYTHONIOENCODING: "utf-8",
```

看起来像个真改动。自证一下就露馅了：**拿同版本的 tarball 与本地安装副本比，差异一模一样。**

## 根因

同一个包由**两条渠道**分发，内容不同：

| 渠道 | `dsh-pwsh-local/lib/index.js` |
| --- | --- |
| 桌面壳 `app.asar` 内置（rc.3 与 rc.5 都） | 17,001 字节，`ENV_OVERRIDES` 含 `PYTHONIOENCODING` |
| npm tarball（rc.3 与 rc.5 都） | 16,816 字节，不含 |

两版 tarball 之间这个文件**逐字节相同**（`sha256` 前 16 位 `8b7b57eb7f6c597c`），两版 asar
之间也相同（`6bea799112c6c282`）。也就是说：**rc.3 → rc.5 零代码变化**，那三行是更早就存在的
渠道漂移。工具拿"安装副本 vs 上一版 tarball"对比，把**跨渠道**差异读成了**跨版本**差异。

## 证据

- `node tools/reconcile-build.mjs --from 0.2.2-rc.5`（同版本）也报同一文件 CHANGED → 差异与版本无关；
- 12 个依赖包在两个版本的 tarball 间逐文件字节相同；`dsh-tools` 等 11 个包的文件数在两条渠道上
  分别 36 / 66（asar 剥掉 `lib/types/**`）、`dsh-config-editor` 203 / 18（asar 内联 `node_modules/js-yaml`）；
- `app.asar` 本身确实变了（273,810,296 → 273,991,626 字节），但**被依赖的包没变** —— 文件大小变了
  也不能当"包变了"的证据。

## 结论

1. **只有同渠道的两份构建可比**：版本间是否变化，用"旧版 tarball vs 新版 tarball"回答；
   安装副本只用来回答"这台机器上实际跑的是什么"。跨渠道对比产出的差异，默认是噪声。
2. **文件数与字节数不作证据**：asar 会少文件（类型声明）也会多文件（内联依赖）。能比的只有
   "两边都有的文件的字节"。
3. **对账工具要自证**：先拿同版本跑一遍 —— 同版本必须全绿；它红了，说明工具在量渠道而不是量版本。
   （与经验 06 同族：先证明仪器能用，再读它的读数。）
4. 这条漂移本身对插件**没有行为影响**，但要记下来：桥面对的 `ENCODING_PREAMBLE` 取自 asar 副本，
   它可能比 npm 发布版新。判断"上游是否已修代码页"要读**安装目录**里的那份，而不是 tarball。
